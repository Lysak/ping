# PING — Localization (i18n) and in-app language switch

Status: **partially implemented.** Device-locale resolution is live; the in-app
language switch is deferred.

## What is implemented

- `res/values/strings.xml` (English, source) + `res/values-uk/strings.xml`.
- `res/xml/locales_config.xml` (en + uk) wired via
  `android:localeConfig` on `<application>` in the manifest.
- Result: language follows the device. English is the base — an en/de/fr/…
  device shows English; only a Ukrainian device shows Ukrainian. A US user
  never lands on Ukrainian.
- Override: **Android 13+ only**, from the OS screen
  **Settings → Apps → PING → Language** (free from `localeConfig`).
  No in-app UI, no restart.

## Deferred (was the rest of this design)

The `AppLocale` object, the DataStore `locale_tag` key, the `<33` Compose
context-wrapper backport and the in-app **Language / Мова** Settings row are
**not built** — there is no Settings/About screen to host them yet. Revisit
when one exists, or if pre-13 in-app override is actually needed. The design
below is kept for that moment.

Note: `minSdk` is **24** in `app/build.gradle.kts` (this doc's body still says 23).

---


The word for this is *i18n / localization* (not "transliteration" —
transliteration is script conversion, a different thing).

## Requirements

- `minSdk = 23` stays. Must work from Android 6 to the current version.
- Languages in v1: **English** (source / default) + **Ukrainian**.
- Default = follow the device: device set to Ukrainian → Ukrainian, everything
  else → English. This is plain resource resolution, no code.
- User can override the language **inside the app** (a row in Settings / About).
- On modern Android the same choice must also work from the OS screen
  **Settings → Apps → PING → Language**, and the two stay in sync.
- **No manual app restart** to apply a change.
- **No new dependency.** In particular no `androidx.appcompat`
  (`AppCompatDelegate.setApplicationLocales` would need it) — see
  `ARCHITECTURE.md`.

## Which API is "current"

The modern mechanism is **Per-App Language Preferences**, added in
**Android 13 (API 33)**: `LocaleManager` + `res/xml/locales_config.xml`. It gives
the OS-level per-app Language screen for free and is the single source of truth
on 33+.

Below 33 there is no OS per-app language screen. The official backport is
`AppCompatDelegate.setApplicationLocales`, but it pulls in `androidx.appcompat`.
We do a ~20-line backport instead (Compose context wrapper).

## Resources

```
res/values/strings.xml      → English   (source of truth)
res/values-uk/strings.xml   → Ukrainian
res/xml/locales_config.xml  → <locale-config> with en + uk
```

`locales_config.xml`:

```xml
<locale-config xmlns:android="http://schemas.android.com/apk/res/android">
    <locale android:name="en" />
    <locale android:name="uk" />
</locale-config>
```

Manifest `<application>` gains `android:localeConfig="@xml/locales_config"`.
It already has
`android:configChanges="...|locale|layoutDirection"` on the activity, so a locale
change does **not** recreate the activity — `onConfigurationChanged` fires,
Compose's `LocalConfiguration` updates, every `stringResource(...)` recomposes
live. That is the whole "no restart" story.

`app_name` stays `translatable="false"`.

## Stored state

One DataStore Preferences key (reuse the existing `datastore-preferences`):

```
locale_tag: String   ""  = follow system (default)
                      "en" | "uk" = forced
```

## Apply logic — one object

```kotlin
object AppLocale {

    // Settings UI calls this. tag: "", "en", "uk".
    suspend fun set(context: Context, tag: String) {
        writeDataStore(context, tag)                 // persistence
        if (Build.VERSION.SDK_INT >= 33) {
            context.getSystemService(LocaleManager::class.java)
                .applicationLocales = LocaleList.forLanguageTags(tag) // "" clears
        }
        // < 33: nothing here — the Compose wrapper below reacts to DataStore.
    }

    // Wraps the whole UI. No-op on 33+ (the OS already applied the locale);
    // active on 23–32.
    @Composable
    fun Localized(content: @Composable () -> Unit) {
        if (Build.VERSION.SDK_INT >= 33) { content(); return }
        val tag by localeTagFlow(LocalContext.current).collectAsState(initial = "")
        val base = LocalContext.current
        val ctx = remember(tag) {
            if (tag.isEmpty()) base
            else {
                val cfg = Configuration(base.resources.configuration)
                val loc = Locale.forLanguageTag(tag)
                Locale.setDefault(loc)               // formatters, etc.
                cfg.setLocale(loc)
                base.createConfigurationContext(cfg)
            }
        }
        CompositionLocalProvider(
            LocalContext provides ctx,
            LocalConfiguration provides ctx.resources.configuration,
            content = content,
        )
    }
}
```

`MainActivity.onCreate` → `setContent { AppLocale.Localized { PingTheme { ... } } }`.

### On startup

Read `locale_tag` from DataStore. On 33+, if it disagrees with
`LocaleManager.applicationLocales` (user changed it from the OS screen), trust
the OS value and write it back to DataStore. That keeps both entry points in
sync with zero extra plumbing.

## Settings / About UI

A single row: **Language / Мова** → dialog with three options:

- *System default* (`""`)
- *English* (`"en"`)
- *Українська* (`"uk"`)

Selecting one calls `AppLocale.set(...)`. UI updates immediately (33+: OS config
change; <33: recomposition). Same dialog on every API level — uniform UX.

Optional nicety on 33+ only: a secondary "Open system language settings" action
via `Intent(Settings.ACTION_APP_LOCALE_SETTINGS, "package:$packageName".toUri())`.
Not required.

## Explicitly skipped

- **RTL handling** — en and uk are both LTR. Revisit if an RTL locale is added
  (`android:supportsRtl` is already true).
- **`androidx.appcompat` backport** — replaced by the 20-line wrapper above.
- **Locale-specific number/date formatting audit** — `Locale.setDefault` covers
  the common case; tighten only if a screen shows locale-sensitive formatting.
- **Per-language Play Store listing / store metadata** — separate task, see
  `COMPLIANCE.md`.

## Test checklist

- `values-uk` has every non-`translatable="false"` key from `values`.
- Device language uk, `locale_tag=""` → UI is Ukrainian.
- Device language de, `locale_tag=""` → UI is English.
- `locale_tag="uk"` on a de device → Ukrainian, no restart, survives process
  death.
- API 33+: change from the OS App-info Language screen → app follows on next
  launch and DataStore reconciles.
- `make gate` + `make verify` clean (Lint `MissingTranslation`).
